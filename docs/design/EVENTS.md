# 表现事件契约

## 边界与接入现状

`js/presentation.js`是独立、无依赖的表现通道。`engine.present(kind, data)`根据数据配置，同时调度动画、粒子、声音、UI通知与相机。相同事件共享 `id`，同一次动作的阶段共享 `castId`。本轮已经接上引擎生命周期、渲染、原音频队列与现有通知槽，但**没有批量迁移旧角色反馈**。

现有 `effects`、`Spectacle`、角色渲染和 `sound()`保留原行为。`Combat.resolveBatch`结束时可以只读记录实际命中；默认不录制、不额外生成任何声音或特效。旧声音可记录请求，但没有动作ID时明确记为旧接口，不猜测其所属技能。

## 数据与时钟

| 字段 | 含义 |
| --- | --- |
| `id` | 系统生成，当前局内唯一；重开后重新计数 |
| `castId` | 调用方提供，同一动作跨预警/释放/命中共享；多实体可用节点/弹丸ID继续关联 |
| `key` | 可选，局内唯一的事实键，用于防止同一事实每帧重播；如 `cast17:hit:target1` |
| `kind`, `stage` | 配置决定表现类型与阶段，不代表发生了新的战斗攻击 |
| `tick`, `simTime` | 引擎固定步长时间；事件申请、视觉及结果按此复现 |
| `actorId`, `targetId` | 标量ID，不把角色对象交给表现消费者 |
| `x`, `y`, `angle`, `color` | 已发生位置与方向快照，不参与寻路、命中或预瞄 |
| `actual`, `blocked`, `avoided`, `outcome` | 战斗结果副本，不能反向用于再次扣血 |
| `notice` | 可选短提示，使用已有角色面板通知；不在场地中心盖文字 |

`audio.request`是申请，`audio.started`是浏览器音频时钟上的实际排入记录；`parentId`连接表现事件。后者只有实验室设置 `Audio.onCue` 时才记录。Web Audio的时钟不是模拟秒数，倍速、暂停和音频限流会造成差别，不能直接相减当作音画误差。被同音色合并或被声部上限跳过的申请，不会冒充已经播放。`audio.started`也不证明人听见或满意。

## 使用方式

在**已有结算完成的命中回调**内选表现，不能在动画回调里生成攻击：

```js
// h 已由战斗模块完成护盾、免疫和实际生命伤害分配。
engine.present(h.avoided ? 'feedback.avoided' :
  !h.actual && h.blocked ? 'feedback.block' : 'impact.heavy', {
  actorId: h.source.id, targetId: h.target.id,
  castId, key: castId + ':impact:' + h.target.id,
  x: h.target.x, y: h.target.y, angle: h.angle,
  actual: h.actual, blocked: h.blocked, avoided: h.avoided,
  notice: h.actual ? '命中' : h.blocked ? '护盾吸收' : '无敌避伤'
});
```

这是接口例子，不要求所有攻击使用重命中配置，也不新增15点阈值或改变现有反馈规则。迁移某个技能时，把原来**同一事实**的反馈一并替换，避免新旧两套声音/镜头叠播；比较迁移前后的同种子战斗快照。未迁移的角色不用顺手修改。

内置配置是通道样例：`impact.light/heavy`、`ability.prepare/travel/release`、`feedback.block/avoided/cancel/resource`。它们不是角色专属美术定稿。专业技能可以增加数据配置或独立渲染样式；不要把全部角色硬套成相同的圆环和同一个声音。

## 隔离与生命周期

- 配置只允许图形大小、余效时长、装饰粒子、镜头幅度和事件音量。没有战斗函数回调或可写角色引用；未知调参字段忽略。
- 表现状态位于 `WeakMap`，不进入战斗快照。装饰用事件哈希，不消耗 `rng` 或 `fxRng`。渲染可更新自身统计，不能推进技能或伤害。
- 新事件通道**没有顿帧或延迟伤害API**。需要真实蓄势、位移、无敌、击退或世界暂停时，战斗/时钟模块显式拥有状态与预算，并独立验证；不从音频/粒子监听器偷偷调用。
- 仅 `running` 接收新表现。暂停不更新年龄和状态，结束不产生新反馈，重开清空事件ID、调参、余效及诊断记录。实验室会主动重新应用选定预设。
- 可记录最终一击所在的结算事件；一旦引擎结束，不再生成新事件。已存在余效停止在结束帧，与原规则一致。
- `key`最多保留1024个；达到上限拒绝新的带键表现并计数，不无限占内存。无键事件仍有活动表现与声音队列预算。时间线保留最近800项并报告截断数。
- 新通道最多24个活动表现，优先降级低强度图形；装饰粒子每帧最多256颗，音频继续使用原32请求/8声部/每帧3启动限制。表现降级不丢伤害。

## 后续迁移顺序

按实际角色任务逐个迁移：先整理该技能事实与阶段→给动作/实体分配关联ID→替换重复反馈→验证取消与无敌分支→对照迁移前后的战斗快照。诊断记录先行，不为统一架构重写所有技能。真实顿帧的不同用途、旧 `Spectacle` 与角色反馈的重复处，留给对应角色迭代解决。
