# 实验室、采集与评审

## 本地使用

直接打开 `tests/presentation-lab.html`，或访问当前本地服务的 `/tests/presentation-lab.html`；团队预览使用 `?mode=team`。无需安装依赖、上传文件或麦克风权限。声音在点击播放/录制后解锁。

选择场景与种子，播放看连续动作，暂停后拖动关键帧或单步。大小、余效、粒子、镜头与音量参数只作用于**新表现通道**，不会改正式技能或写回角色配置。滑块会按同一种子重放到当前帧，方便比较；改旧角色音画仍需针对其模块实现。

| 场景 | 用途与边界 |
| --- | --- |
| 轻/重命中 | 真实调用伤害分配函数得到结果，再发出统一表现；固定摆位与伤害是测试夹具，不是角色平衡 |
| 护盾/无敌 | 验证不同结果不会都演成成功伤害；模拟防御状态，不更改角色定义 |
| 取消 | 准备到取消，无伤害，无命中重音 |
| 多阶段样例 | 同一动作ID关联准备、移动表现、释放和命中；不是普通球奥义的实现 |
| 角落 | 检查裁切、方向和反馈中心 |
| 密集事件 | 压力与层级预算，装饰请求不结算伤害 |
| 真实对局 | 正式引擎与角色的六秒自然样本；不因新通道开启而改变规则 |

当前夹具只使用普通、加速、吸血三种角色；团队预览用开阔场。以后技能任务按需加入其真实成功/落空/打断/掩体场景，不把受控伤害样例当成全角色验证。

## 采集与复现

- **PNG**：当前Canvas关键帧；不含页面外UI，UI评审另拍整页。
- **事件JSON**：版本、种子、模式、球种、帧号、参数与有限时间线。模拟事件可复现；音频排入记录受浏览器时钟与声部调度影响。单步/定位不会播放历史声音。
- **参数JSON**：实验预设。可以通过 `feelLab.scene/seed/tune/seek`按字段恢复；自动脚本与截图一并保存预设。不同代码版本不承诺种子产生相同结果。
- **画面＋声音WebM / 仅声音WebM**：先点录制，再播放，结束后下载。声音从现有压缩器输出旁路采集，包含实际混音、静音与尾音；不录麦克风，不请求全屏桌面采集。浏览器缺少接口或编解码支持时明确降级为PNG/JSON，不声称录制成功。
- 单段录制上限12秒，最多暂存8段，结束/离开释放媒体轨道。音频文件有效、可解码、有波形都不等于主观好听。

自动采集（开发工具可选，游戏运行不需要它们）：

```powershell
node outputs/orb-duel/tests/verify-presentation.cjs
node outputs/orb-duel/tools/capture-presentation.cjs
```

以上从项目根目录执行。采集脚本需要 Node 与可用的 Playwright/Edge；优先使用已安装模块，也可通过环境变量 `PLAYWRIGHT_MODULE` 指定模块位置、`BROWSER_CHANNEL`指定浏览器通道。不会自动安装依赖。默认写入项目 `work/presentation-review/`，保存关键帧、整页截图、时间线、参数、代码哈希与检查报告，并实际尝试录制视听媒体。可用 `--out 绝对目录`另选输出位置。

## 评审顺序与证据

1. **正确性门槛**：开启/关闭表现与诊断时战斗快照及随机流一致；暂停、结束、重开、去重、预算和非法参数正常。涉及玩法才运行其专项，不无理由跑全角色长对局。
2. **静帧观察**：在实际网页尺寸和缩小画面看主形、方向、危险区、角色轮廓、UI和叠放；记录看过哪些图片，不能只报“截图生成成功”。
3. **连续动作**：检查前后姿态、转场、运动速度、预警/锁线/接触/收势关系、落空与取消。需要停顿时说清目的；不能由单张截图推断动作协调。
4. **声音与同步**：在真实混音中试听，核对请求和实际排入事件、成功/防御/失败分支、组音效、尾音与静音清理。未试听就写“未试听”；人工判断重量、材质、庄重感和爽感。
5. **层级与负载**：检查普通/强化/关键技能的对比，1×及加速播放、1v1及受影响的2v2。记录装置、窗口、采样量、渲染调用P50/P95、活动数与降级数；不能把短样本的函数耗时当成稳定FPS。
6. **兼容性**：Windows目标浏览器、本地文件、窄屏、音频解锁/静音、减少动态效果、可用录制接口。没有跑过的浏览器列为未验证。

报告采用分离字段：`objective`（工具结果）、`visualReview`（观察者和实际看过的素材）、`motionReview`、`audioReview`、`performance`、`remaining`。自动脚本将主观项初始化为 `not-reviewed`，开发者只能在实际完成对应观察/试听后更新。不要自动写“高品质”“很有力气”。

先完成明确标准，再做约两轮有针对性的审美迭代；正确性失败继续修复，口味未定保留具体片段与待选项，不无限打磨或反复请求抽象批准。

采集接口参考：[Canvas媒体流](https://developer.chrome.com/blog/capture-stream)、[MediaStream Recording API](https://developer.mozilla.org/en-US/docs/Web/API/MediaStream_Recording_API)、[音频输出媒体节点](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamAudioDestinationNode)。
