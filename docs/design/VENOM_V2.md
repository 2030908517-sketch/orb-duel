# 毒液球 V2：正式机制与调参

版本：20261017-venomfeel1。经典1v1、奥义模式常规部分、2v2共用；奥义「腐生·万毒缓蚀」、血量和心跳保持原机制。旧自动毒爆、剩余毒伤折现、旧共鸣范围伤害与三向液滴生成路径已移除。

## 毒层与时钟

侵蚀与麻痹共用4槽、单类最多3层，每层保存类型、来源、创建时刻与到期时刻。每个来源对同一目标的碰撞、毒弹和全部区域共用1.1秒施毒间隔；换区域、反复进出、净化均不返还已消耗的间隔。两名毒液球各自拥有施毒间隔，但共享目标容量、替换进度和替换冷却。

未满槽时新增；同类已达3层时只刷新该类剩余最短的一层，其他层不刷新。满槽且该类仍有容量时，每次有效施加累积一次进度，2次后只替换对方剩余最短的一层。替换后目标进入2秒冷却，期间进度最多积到2，但要等冷却结束后的下一次有效施毒才替换。掉层、补层仍正常；所有层自然到期也不会提前返还替换冷却。非满槽时清空不再适用的替换进度。

侵蚀每0.5秒按当时有效侵蚀层数结算，不消耗层数、不折现被替换层，不因新施毒、替换或进出区域重置时钟。净化清掉毒层和替换进度，但不清奥义伤害池、不返还已花费的施毒/替换CD；重新施毒仍沿原固定结算相位。毒雾低额区域伤害另有时钟，不靠反复进出加快，也不按重叠毒雾数量叠加。

## 三态与控制

普通池主要施侵蚀；浓缩池变小，侵蚀层持续更久，每两次有效施毒额外施加一次麻痹（可补层或积替换进度）；雾变大，主要施麻痹、低额区域毒伤及只在雾内的普通瞄准扰动。同源区域重叠优先选择雾、浓缩、普通池，每次只处理一处。同源同目标毒雾低额伤害也只结算一次。池及雾不能穿过团队障碍、陷阱囚笼和护盾奥义城墙；离场/无敌/虚化及友伤按现有规则处理。

麻痹降低实际移速，不改存储的基础速度、超速挡位、技能CD或时间流速。仅降低对外普通身体碰撞伤害；冲刺、重拳、压力强化、接刃重击、动能强撞及奥义等专属强攻击排除。普通瞄准转向与雾中扰动接入现有瞄准，兼容激光、射手、飞行时钟、毒弹、反击预瞄，以及加速/幽魂的预瞄；霸体免疫移动与瞄准控制，奥义瞄准不受影响。

觉醒共鸣预警后将己方毒液推进下一态；已有雾只延长少量时间，每池累计延长有上限。三态采用时间驱动；没有独立测试模式或额外测试界面。

下一轮优先调：施毒间隔与毒层时长的比例（能否形成4槽结构）、替换次数/CD（取舍是否稳定）、三态半径/时间（能否实际接触到雾）、麻痹三项比例（近战与瞄准的体感）、最后再调侵蚀与雾伤。不是最终平衡结论。

## 观察和验证

93项新机制定点检查；原伤害池107项、心跳14项、奥义交互141项、时间回溯861项、声音政策270项通过。只将时间回溯专项的旧毒爆冷却断言换成新共享施毒冷却断言，没有改时间球规则。

正式三个入口各运行10秒定向对战，未出现异常数值、页面错误或旧毒爆。实际打开并查看三态同场、自然演变的有序帧、团队画面与手机尺寸截图。首轮毒雾形状过于规则像花瓣，已改错落云团并重新观察；绿点/紫菱形槽位在球旁可读，毒层增减实时跟随战斗。截图与调用结果在本聊天outputs/venom-v2。没有主观试听（音色沿用已校准资源）、没有进行大规模平衡测试。

开发者控制台可用 `OrbDuel.Venom.inspect(目标球, 当前引擎)` 查看各层类型/来源/剩余时长、替换进度与冷却、施毒门限和跳伤时钟；不会新增游戏UI。

### 外周标记更新（markers1）

移除场内毒层文字、毒池种类名称及池内弧线/泡圈描边，面板只保留中毒状态而不显示当前毒层文字。所有资源点数与印记统一由js/renderer.js的G.OrbMarkers收集和绘制，统一半径3.5，保留颜色与符号差别；自身点数位于上侧、毒层左下、其他印记右侧，过多印记使用固定第二层。没有贴墙裁位或邻球避让，按用户要求随球体固定移动。原技能范围、护盾、瞄准线、伤害与毒素计时均不改变。128项标记专项、93项毒液机制专项及三个正式入口验证通过；实际查看密集印记和手机画面。

markers2：统一尺寸但取消通用圆形底框，保留各类图形特色；球面到标记中心距离改为8，仍固定分区、不避让。128项标记检查及三个正式入口通过，实际查看桌面/手机画面。

markers3：毒层圆点缩小、菱形放大以校准视觉重量，各印记按轮廓分别补偿，不再要求完全相同的物理尺寸；血能为等距直排的血色晶滴。仅改变绘制。

## 自然毒区与布池间距（20261017-venomfeel3）

毒雾统一麻痹菱形紫色#c6a2ff；视觉外缘自然起伏，收缩/汽化连续演变，进入反馈增强。新增可调 `G.Venom.config.poolGap=8`：同一来源新区域按双方最大形态半径留空，优先原位、否则最近合法空位，不跨城墙/牢笼/掩体；实在无处可放则不生成，原放池CD沿用。上限检查找到新位置后才回收最早池。旧区域不移动，跨来源重叠沿既有结算，不改双毒与奥义机制。
