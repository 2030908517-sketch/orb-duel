# 01 · Game Feel 与 Juice

[索引](README.md) · 关联：[打击](03-impact-and-collision.md)、[奖励](07-positive-feedback.md)

本章把 Game Feel 作为运动、规则、反馈和理解共同形成的体验，把 Juice 作为强化事件感受的表现手段。它们相关但不等同。这是本库的操作性划分，不宣称学界已有唯一公认定义。

## GF-01 · 因果可读性先于装饰数量

**原理与心理。** 观众先要将“谁做了什么”和“出现了什么后果”关联起来。若每次出手、落空、护盾吸收都播放相同的大爆炸，事件虽然显眼，成功与失败却失去差别。感觉强烈可以来自后果明确，而非刺激总量。S02 的实验提醒反馈是否关联成功很重要；其具体心理中介仍是作者假说。

**适用与协同。** 一切攻击都需要一条可追踪的因果链；尤其适合拆解“很炫但不知道打到没有”。让出手音描述动作，命中音描述接触，血条/UI 确认实际结算，位置变化交代方向。几种手段分担不同问题，不是重复喊同一句话。

**误用反例。** 假设一颗子弹擦墙时也播放破盾般的亮闪，观众会误认其伤害与机制。相反，全部取消落空反馈也不好：出手过程仍应成立，只是不能伪造命中奖励。

**案例与来源。** S01 的 Downwell 案例分析关注动作的视听响应及其协调；S02 为“成功关联”提供不同类型的实验依据。前者是分析框架，后者是特定游戏实验，二者不是同一种证据。[S01](SOURCES.md#s01)、[S02](SOURCES.md#s02)。

**ORB 建议。** 对真实碰撞、盾吸收、无敌穿过、射空各自明确“动作成立”和“伤害成立”的差别；结果从战斗事件读取。不能由画面亮度推断或制造生命伤害。

## GF-02 · 强度来自对比，不等于全程克制

**原理与心理。** 一个事件的特殊性，需要可比较的普通状态。持续高亮、持续轰鸣、持续慢动作会压缩可表达的差异。这里的“对比”包含空间大小、声音占据、变化速度、形状、持续时间和出现频率，并非只能让奥义更响。

**适用与协同。** 为少见、重要、符合角色性格的事件集中资源。大招可有长蓄势与巨大主体，同时减少不相关碎屑；低伤持续地面场可长期存在，但降低内部运动，让轮廓表达危险。

**误用反例。** 为了给大招留空间，把所有小技能变得无声无色，会削弱角色日常魅力。另一极端是每次持续伤害都用爆发层级反馈，导致真正的爆发无法再被区分。

**案例与来源。** Riot 明确允许重要技能显著，并把跨专业的突出程度作为共同预算；触觉实验也没有发现强度提升在所有指标上继续获益。但这些都不规定 ORB 的最大特效尺度。[S07](SOURCES.md#s07)、[S03](SOURCES.md#s03)。

**ORB 建议。** 建立的是“普攻、强化、觉醒、奥义各自怎样有存在感”的关系，不能简单规定奥义比普攻粒子多几倍。先选一个主导维度：拳是力量释放，闪电是速度与路径，神圣是秩序与仪式。

## GF-03 · 一致性让观众学会规则，变化让具体事件鲜活

**原理与心理。** 重复的语法降低理解成本；局部变化避免机械复制。若每次变化都改掉核心线索，观众需要重新学习。可识别的稳定部分与不影响判断的变化部分应分开。

**适用与协同。** 保留同一角色的核心形状、起音或动作节拍；在碎屑分布、非语义纹理、小范围音色中变化。反馈变化应能解释为不同接触、强度或阶段，而不只是每次随机换风格。

**误用反例。** 同一个反伤成功有时是玻璃碎、有时是重鼓、有时是钟声，表面丰富却难以辨认。反过来，每一次攻击复制完全相同的长尾，也容易产生整齐叠加的机械感。不能凭 S02 关于随机变化的结果断言所有变化均无用。

**案例与来源。** Overwatch 讲义将有限变化与声音辨识联系；VALORANT 给武器建立可学节拍。这些是开发者实践，不是所有游戏只能用一个采样。[S10](SOURCES.md#s10)、[S11](SOURCES.md#s11)。

**ORB 建议。** 角色身份尽量由“形状＋运动语法＋音色包络”共同支撑。非战斗随机变化使用独立表现随机源，不能改变种子对局结果。

## GF-04 · 自动观战的正反馈是“理解和预期得到兑现”

**原理与心理。** 操作者通过输入与结果建立掌控；观众的可能收益是预测成功、看出连锁、支持的角色扭转局势。把观众也叫玩家，不会使两类动机自动等价。此迁移是待验证的项目假说。

**适用与协同。** 表现可以提前让观众知道资源将满、抓捕将成立、反击机会将出现；释放后用结果确认。需要状态线索与爆发演出合作，单独的大字“强力”不能代替铺垫。

**误用反例。** 为没有操作的观众不断显示“完美操作”，与其实际贡献不符；每次觉醒都长时间挡住小球，也会错过真正值得看的交互。

**案例与来源。** S21 的需求满足框架主要解释游玩者；S01 的 Candy Crush 分析展示连锁反馈，但两者都没有直接验证小球观众。本库仅借其“反馈需要有意义”的问题意识，不照搬用户动机。[S21](SOURCES.md#s21)、[S01](SOURCES.md#s01)。

**ORB 建议。** 未来评审优先问“你期待接下来发生什么”“你认为什么造成了这次逆转”，而不只问“炫不炫”。保留随机战斗的不确定结局，同时让局部规则能够解释。

## 本章的判断顺序

先检查事件是否可理解，再检查是否符合角色，最后调整强度。S01 的开发者经验、S02 的实验和 S03 的触觉结果共同反对一个过于简单的推论：**把反馈总量一直往上推，就能一直提高体验。** 它们并没有共同证明一个最佳强度，也没有否定夸张的大演出。
