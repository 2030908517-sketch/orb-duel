# ORB DUEL 长期设计研究日志

建立日期：2026-10-21。本文件目前只建立结构、状态和维护规范，**没有填入虚构的历史研究、采纳记录或创作者反馈**。第一阶段代码分析仍在原事实文档中，不自动算作某个新方案获批。

## 1. 每次怎样接续

先检索相关角色、机制、旧方案及否决原因，再选新问题或继续旧ID。先看下方索引及最近更新，不要求通读全部记录。无回应不代表否决，方案存在不代表采纳，代码已存在也不能反推当年批准过程。

日志的用途是保留问题、推理、证据、决定和后续入口。事实仍以角色/系统文档及当前代码为准；未经实装确认的提案留在日志，不能写进“已实现机制”。

## 2. ID与索引

- 正式研究ID采用 `R-YYYYMMDD-NNN`：日期为首次建项日期，序号从001起；这是格式，不是一条真实记录。建项前检查现有ID，永久保持不变、不循环复用。
- 同一问题、同一方案的推进继续原ID，保留简短更新历程；实质不同的备选方案、分支或替代方案新建ID，并关联原项。
- 索引只写实际存在的条目。标题和标签应能检索角色代码键、技能、模式和机制，如“有限跟瞄/接触机会/临时边界”。不要只写“今日灵感”。

## 3. 状态定义：不能把进度当批准

| 状态 | 使用条件 | 不代表什么 |
| --- | --- | --- |
| 待研究 | 已登记具体问题，尚未完成研究 | 问题已证实或必须修改 |
| 已提出 | 有明确假设/方案及依据，等待讨论或下一步 | 创作者批准、实现可行已验证 |
| 待验证 | 明确列出需要的证据或实验 | 已获实验授权或测试已通过 |
| 已验证 | 指定结论在明确范围内得到证据支持，记录方法和限制 | 所有模式、平衡、表现都通过；整个方案必然优秀 |
| 已采纳 | 创作者明确确认具体方案及范围，留可追溯来源 | 已实装、已测试或允许附带其他改动 |
| 已否决 | 有明确否决决定及适用范围；创作者决定需记录来源 | 没回应、无限期禁止整个设计类别 |
| 需要修改 | 明确存在需修订处，说明来自创作者还是AI自评 | 整个方向被否决 |
| 已废弃 | 条目因被替代、前提失效或不再适用而停止使用，说明原因 | 现有游戏机制已被删除；仍保留历史记录 |
| 已完成 | 本条研究目标已完成，结论、剩余问题和去向清楚 | 自动等于已采纳、实装或全局平衡通过 |

主状态用于索引，必要时另列两栏：**决策情况**（未反馈/讨论中/明确采纳/明确否决）、**验证情况**（未验证/部分验证/具体范围已验证/证据需复核）。例如已采纳的方案仍可未验证；已完成的分析也可以没有任何获批改动。

状态不强制线性流转。发现反例、源码变化或实验失败可以退回待验证/需要修改，保留变更原因。AI可以自评“当前方案需修改/当前假设被证据否定”，但不能把它写成创作者否决。已采纳必须有创作者明确确认；含糊反馈先保留范围，不推断全面批准。

## 5. 证据和决定怎样记录

### 验证

写清被验证的命题、条件、方法、版本与结果。代码确认可验证某个门槛或调用顺序，不能替代命中率/胜率实验；截图不能代替连续动画观察，波形不能代替试听。负结果同样有价值。

数值试验记录模式、角色、地图、种子、手动输入、样本量、统计口径和异常；未运行就只写实验建议。旧测试在源码变化后标“证据需复核”，不覆盖成新结果。原始审计结果和事实快照不因日志结论改变而被重写。

### 采纳与否决

明确反馈后记录决定对象、版本/范围、理由与来源。否决原因可包括身份不符、机制重复、触发不足、没有解决原问题、平衡风险、底层冲突、演出不适合、成本过高或创作者不喜欢；**只记录实际给出的原因，AI解释另标推断**。

“不做这版三段射击”不自动等于“永久禁止所有多段攻击”。后续若前提改变，可关联旧ID解释为什么值得重开；不能删除旧否决原因后原样再提。创作者批准研究，也不等于批准改代码、发布或运行大规模测试。

## 6. 持久化与长期维护

1. 写入前确认可访问的持久位置及授权范围；仓库、本地文件与Issue不是天然同一个副本。云端任务不能假设可读本机路径或继承上次完整聊天。
2. 有仓库写入授权时，只更新日志/明确授权的研究Markdown；先读最新内容，合并新增，不覆盖他人记录。多人写同ID冲突时保留两方证据，不能直接覆盖。
3. 文件过长时，可把真实条目拆到 `research/<ID>-<slug>.md`，本页保留索引、决定摘要和链接；不提前创建大量空文件。否决、替代和未决问题仍可检索。
4. 若只能通过授权的其他文件或Issue保存，明确唯一主记录地址、版本及关联ID；不要在两个位置维护互相矛盾的“最新状态”。发Issue/消息或上传需对应授权，日志规范本身不授予外发权限。
5. 没有授权/写入能力或写入失败：输出带ID或待分配ID的待保存条目及原因，不说“已保存”。成功后检查目标内容，再报告位置。没有可访问的历史时说明研究连续性受限。
6. 新实装须由有授权的开发任务确认，再更新事实页和受影响的交互/模式说明；采纳提案本身不触碰事实页。新运行结果另记，第一阶段审计保持其日期与证据身份。
