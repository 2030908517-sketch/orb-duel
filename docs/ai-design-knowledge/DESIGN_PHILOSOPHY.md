# ORB DUEL 创作理念与设计判断

整理日期：2026-10-21。主要依据：创作者在“游戏设计知识库第二阶段：创作理念与自主研究体系”中的明确说明，包含补充的每日研究要求。本文保存设计立场，不重新定义已实装技能。游戏事实仍查 [GAME_SYSTEM](GAME_SYSTEM.md)、[角色档案](CHARACTERS.md)和当前代码。

## 1. 先分清一句话属于什么

| 类别 | 含义与本库位置 | 如何使用 |
| --- | --- | --- |
| **创作者已确认原则** | 本文第2～8节，来源为本次明确要求；已有项目规范另见 [DESIGN_CONSTRAINTS](DESIGN_CONSTRAINTS.md) B类 | 指导取舍，不把倾向擅自升级为绝对禁令；改变原则需要创作者确认 |
| **当前实现约束** | GAME_SYSTEM、角色页、模式页、DESIGN_CONSTRAINTS A类及源码 | 决定今天实际能发生什么；代码可改变，但研究建议不是修改授权 |
| **AI推导的建议** | 本文第9节的审查方法及未来研究日志中的设计推导 | 可反驳、可迭代；不得标为创作者已决定或现有功能 |
| **未确认偏好** | 本文第10节及研究日志中的待确认项 | 写出具体取舍和影响；不自行代填答案，也不因非必要偏好阻断所有研究 |

事实与意图是两个维度。代码证明“当前怎样执行”，创作者说明“希望怎样设计”。两者不一致时记录差异，不用原则文字静默改写事实，也不用旧代码否定创作者的新意图。AI推理、实测结果、采纳决定分别记录。

## 2. 创作定位：深度服务作品，不服务复杂度

创作者希望构建机制体系完整、内部逻辑自洽、角色特色鲜明的游戏。更看重机制独特性、有机联系、角色完整性、底层一致性、战斗表现的真实感与协调反馈，以及自己对作品的认可。

ORB DUEL不以不断加入简单角色、热梗、流行元素来快速生产短视频为创作目标，不为流量牺牲上述理念。录视频和观赏传播是使用场景，不能反过来成为所有设计的唯一理由。

**复杂度不是目标，设计深度才是目标。** 简单机制不天然低级，多机制不天然优秀。少量规则若能在运动、空间、资源和对手反应中产生丰富关系，也可以形成完整角色。增加说明长度、状态数量或触发层数，本身不能证明设计有价值。

## 3. 完整角色：能力之间应当有理由

每个角色需要明确的核心身份和战斗主题，技能不是彼此独立的能力清单。研究时考虑：核心机制如何建立身份，各能力怎样联动，是否形成完整循环，觉醒如何扩展或改变循环，奥义如何利用已有体系，以及独特优势、弱点与反制空间。

毒液主题可以围绕毒素积累、场地、持续伤害和既有感染机制形成系统，而不止“普攻加毒”。这是思考方向，**不是要求所有角色都复制毒液的技能数量或结构**。现行毒液事实以其 [角色档案](characters/venom.md)为准。

避免仅更换外观、元素或名字复用其他角色能力；也不为追求差异而拒绝所有共用底层工具。关键是共用的碰撞、弹丸或范围判定，在这个角色的决策、资源、空间关系与战斗循环中产生什么不同作用。

## 4. 实际环境：文字成立不等于战斗成立

方案必须放回真实竞技场、自动反弹运动、球体体积、动量与墙反射、预瞄、伤害结算、AI及模式输入中理解。

研究需要区分“理论可以触发”和“实际存在足够触发机会”。例如长时间追击可能被小场地、反弹、身体接触或击退打断；若当前AI不会制造追击条件，仅写一个连招就不能证明角色能用好它。手动玩家的选择权也不能当成自动敌方的能力。

没有运行证据的实战效果应写为假设，并指出依赖哪些条件。静态代码能确定硬门槛和执行顺序，通常不能独立确定命中率、常见程度、胜率或观看感受。按需回查相关代码，不要求每次重读全项目。

## 5. 奥义：身份、痛点、创意、演出

创作者当前的优先级为：

1. **契合角色身份。** 让人感到是这个角色独有的能力，而非另一奥义换色。
2. **解决真实痛点。** 补足真实战斗中的缺陷，或打开此前缺少的战术可能；先确认痛点，不为给奥义找理由而编造问题。
3. **创意与新颖性。** 避免只提高伤害、范围或持续时间；研究是否引入新的交战关系。
4. **视听演出。** 有令人印象深刻的动作与反馈，但不能掩盖机制失效或重复。

这是取舍指导，不是四项打分相加，也不要求所有奥义按同一阶段数、同一反制方式实现。演出位列第四，不等于可以忽略表现完成度；实用性、视觉、动作、音效仍需协调。

现有倾向是避免高额直接斩杀、不受限制的永久强化、缺乏反制空间的强制胜利，以及与身份无关的纯表演。它们是设计倾向，不用于擅自宣判已有技能无效或废弃。具体触发、次数、防御交互和例外，查当前实现与已确认方案。

## 6. 平衡：长期有反制，不要求每局险胜

创作者重视长期对战平衡，目标是避免大量对局中长期、严重且缺乏合理反制的压制，而非要求每场势均力敌或每个配对完全相同。

分析必须分开：单场随机结果、长期总体胜率、特定对阵胜率、机制上可能的克制、实战有效克制、理论收益、触发频率，以及强度与观赏体验。

代码可以支持风险判断和实验建议，不能凭阅读声称胜率过高/过低。一个理论很强但很少满足条件的能力，与稳定高收益能力不同；偶然秒杀、一次落空或一次逆转，都不能代表长期表现。没有数据时明确“待验证”，不填猜测百分比。

## 7. 表现：协调的力量，而非堆满屏幕

创作者重视爽感、真实感、观赏性、流畅性与正反馈。准备和蓄势、释放、运动逻辑、命中、停帧、音效时序、信息层级和结束收束需要共同表达一件事：观众能理解发生了什么，并感到与机制相称的力量。

特效多、声音大、画面亮，不自动等于有打击感。停顿应表达预期或命中重量，动作应有连贯的受力与方向，高潮应有层级，复杂演出不能淹没球体、危险、血量变化及有效命中。

具体标准复用 [PRESENTATION](PRESENTATION.md)、[项目表现入口](../design/README.md)、[画风锚点](../design/STYLE_ANCHORS.md)、[参考规范](../design/VISUAL_REFERENCES.md)、[音频规范](../design/AUDIO_MIX.md)和[专业知识章节](../design/knowledge/README.md)。本文不另定画风或混音参数。代码读到“震屏/爆炸”不能证明效果好；没观看、没试听，就不能声称通过视听评审。

## 8. 创作评价：独立、具体、有依据

AI应保持独立判断，不因投入时间多就默认优秀，也不为显得专业而找不存在的问题。认可应说清哪个机制关系、动作或取舍有效；反对要说明问题、成因、发生条件、证据、改进方向及其新风险。

允许得出“现有角色不需要新技能”“问题在触发机会而非伤害”“这一方向值得保留但仍缺验证”。有依据的反驳与创造性探索受到鼓励，空泛赞美、机械否定和脱离本游戏环境的通用建议没有替代作用。

## 9. AI可采用的审查方法（推导建议，非新增创作者决定）

### 痛点的证据链

把痛点写成“在什么模式/条件下，哪一步循环受阻，造成什么后果”，再区分证据：

- **事实**：条件、分派、资源、AI和执行顺序已确认。
- **原因假设**：这些事实可能怎样导致问题；同时检查相反情境和原有补偿。
- **实战缺口**：是否常见、损失多大、玩家是否困扰，尚需何种观察。

先检查已有能力是否已缓解痛点。不能将有意保留的弱点、允许落空或某个对手具有优势，直接命名为必须修复的缺陷。若补足弱点会抹去角色差异，应说明代价。

### 识别换皮、重复与无意义复杂化

与最接近的既有机制比较：**决策条件 → 核心资源 → 空间/时间关系 → 实际动作与命中 → 收益与反制 → 结束后循环**。不必每次都填完整表，但应能解释实质差别。

如果仅换色、加弹数或加伤，而这些关系几乎不变，应说明重复风险。相反，即使复用弹丸，只要它重构了资源、控制或交战机会，也不应只因外形相似就否定。比较结论属于设计分析，不自动授予采纳或否决状态。

对每项新机制追问：删掉它会失去什么有意义的关系？如果只增加例外、UI负担和维护成本，收益又没有证据，可以简化或暂不增加。不要用固定技能数量衡量角色完整度。

### 判断一份方案是否值得讨论

至少能回答角色为什么需要它、当前系统能否让它发挥、与近似方案哪里不同、怎样保留弱点、最关键未知是什么。缺少证据时可以只提出一个好问题，不必凑成完整技能；也应适时主动尝试不同机制关系，不能长期只重复代码盘点。

## 10. 差异与未确认偏好

以下不阻止当前文档使用，后续遇到相关取舍再询问，不预设答案：

| 项目 | 已确定/当前事实 | 尚未确定的部分 |
| --- | --- | --- |
| 持续型奥义 | 原则倾向避免不受限制的永久强化；当前毒液缓蚀持续改变伤害支付结构 | 不把倾向解释为废弃缓蚀；未来哪些持续结构可接受，需具体方案确认 |
| 平衡标准 | 避免长期严重、缺少反制的压制；不是每局险胜 | 可接受的总体/对阵差距、样本量与模式权重未给统一阈值 |
| 模式侧重 | 自动观赏是基础；手动和团队已存在，各自有约束 | 某方案主要为哪种模式服务、是否要求跨模式等效，不能总由AI代定 |
| 机制复杂度 | 深度优于数量，简单也可优秀 | 没有统一技能数/状态数预算；按实际收益与理解成本讨论 |
| 视听取舍 | 复用已确认画风和规范，清楚、有力、协调 | 新题材的具体参考与夸张程度仍须结合场景，不能用一个锚点批准所有美术 |

上述均未设置虚构创作者反馈。新增确认应记录来源、日期和适用范围，再更新本文；一次方案否决不等于永久禁止一个机制类别。
